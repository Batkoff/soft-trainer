Пользователи и роли

  1. Администратор открывает Пользователи → «Добавить пользователя».
  2. Указывает логин, имя, пароль и одну роль. Руководителей и администраторов добавляем тем же способом.
  3. Чтобы закрыть доступ, снимает «Активный» в карточке. «Последний вход» заполняется автоматически. Пароль можно сбросить по ссылке в карточке.
РольДоступ
СотрудникСвои конкурсные задания, профиль и рейтинг своего конкурса.
РуководительПесочница, аналитика, просмотр заданий и всех работ пилота, пересмотр оценок и повтор неудачной проверки.
АдминистраторВсё перечисленное, управление пользователями, заданиями, конкурсами, призами и калибровкой.

Разделения руководителей по отдельным командам пока нет. В пилоте руководитель видит все работы. Ник и аватар сотрудник выбирает в «Мой профиль».

Создать или изменить задание

  1. Откройте Задания → «Добавить». Заполните сообщение клиента и исходный hard-ответ.
  2. В «Обязательных фактах» укажите по одному утверждению на строку. Сроки, суммы и условия описывайте точно. Допустимые действия и запрещённые обещания помогают оценщику не выдумывать факты.
  3. Сохраните черновик. Его поля можно редактировать прямо в карточке.
  4. В списке отметьте черновик, выберите «Опубликовать выбранные черновики» и нажмите «Выполнить».
  5. Чтобы изменить уже опубликованное задание, откройте его и нажмите «Редактировать новую версию». Измените и опубликуйте копию. Затем выберите её в новом конкурсе: текущие ответы и действующий конкурс сохраняют старую версию.

Запустить конкурс

  1. Откройте Конкурсы → «Добавить». Задайте название, даты и призы. По умолчанию — 5 заданий в день, 180 секунд на ответ и фонд 100 / 70 / 50 T‑Money.
  2. Добавьте опубликованные задания и участников. Если хотите сами проходить рейтинговые задания, добавьте и свой аккаунт администратора. В стартовый черновик admin уже включён.
  3. Сохраните. Отметьте конкурс в списке → «Запустить выбранные конкурсы». После запуска состав участников, задания, сроки и профиль оценки фиксируются.
  4. Все сроки — МСК. Время по умолчанию 00:00:00, без миллисекунд. Для быстрой проверки можно задать конкурс на пять минут.
  5. В карточке конкурса нажмите «Завершить досрочно» и подтвердите. Приём прекратится, сохранённые черновики уйдут на проверку. Когда все проверки и пересмотры закончены, итоги зафиксируются автоматически в течение минуты. Для немедленной фиксации нажмите «Проверить и зафиксировать итоги».
  6. Итоговый рейтинг доступен через Рейтинг → Завершённые конкурсы. На главной выбирается следующий доступный конкурс. Новый создайте и запустите отдельно. После фиксации результаты неизменны; автоматической выплаты T-Money нет.

Для обычной проверки функциональности администратор всегда может открыть Песочницу: доступны те же задания и таймер, без рейтинговых баллов.

Пересмотреть оценку

  1. В «Аналитике» или Попытках откройте работу сотрудника. Вверху указан автор.
  2. Нажмите «Пересмотреть оценку», проверьте hard-часть, измените значения пяти soft skills и напишите причину.
  3. Итог пересчитается автоматически. Существенная hard-ошибка даёт 0; разбор навыков остаётся виден. Первоначальная оценка сохраняется, каждое изменение записывается в журнал.
  4. Если API не дал разбора, можно «Повторить проверку» после исправления настроек либо оценить работу вручную. После фиксации итогов конкурса пересмотр закрыт.

Подключить нейросеть

  1. Откройте настройки нейросети под суперпользователем.
  2. Выберите провайдера, модель и вставьте ключ. Сохраните настройки; перезапуск не нужен.
  3. Отправьте ответ в песочнице и дождитесь разбора.
  4. Создайте или откройте черновик конкурса, проверьте даты, участников и задания. При запуске закрепится текущая модель.

Старые конкурсы с тестовым оценщиком сохраняют историю. Для реальных оценок создайте новый конкурс. Ключи доступны только суперпользователю.

Если что-то не работает

  • Администратору недоступны ежедневные задания: запустите обновлённый seed_demo — он добавляет admin в демо-конкурс. В новом конкурсе добавьте аккаунт вручную.
  • Старая вёрстка: выполните docker compose up --build -d, затем Ctrl+F5. Версия внизу страницы должна быть {{ app_version }}.
  • Долго идёт проверка: откройте docker compose logs --tail=100 worker. Для полного промпта и ответа откройте админку → «Диагностика API» и нажмите «Скачать .txt». Кнопка «Скачать этот список .txt» выгружает записи с учётом фильтров. Журнал действий тоже выгружается в TXT; формат JSON сохранён.
  • «Сбой · назначен повтор» — история конкретного запроса. В его карточке отдельно показано состояние работы сейчас: проверена, ждёт очереди или требует администратора. Успешные события зелёные, ошибки красные, назначенные повторы жёлтые.
  • Отключение модели не превращает ответ в нулевой балл. После трёх неудачных запросов нужна помощь администратора. Старую ошибку цитаты можно проверить заново кнопкой «Повторить проверку» в работе сотрудника.
