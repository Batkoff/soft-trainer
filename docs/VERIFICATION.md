# Проверки проекта

## Полная проверка через Docker

```bash
python scripts/start.py
docker compose exec -T web python manage.py check
docker compose exec -T web python manage.py makemigrations --check --dry-run
docker compose exec -T web python manage.py test trainer
python -m unittest discover -s scripts -p "test_*.py"
```

Тесты Django используют отдельную тестовую базу PostgreSQL. Не запускайте их с учётной записью production-базы: выполняйте проверки в собственной копии Compose.

В GitHub Actions проверяются сборка образа, запуск на чистой базе, доступность страницы входа и health endpoint, миграции и тесты приложения. Workflow находится в `.github/workflows/ci.yml`; его статус нужно смотреть в Actions конкретного коммита.

## Что покрывают тесты

- Дневной лимит, сохранение ответа, серверный дедлайн и повторная отправка.
- Очередь, временные ошибки API, исчерпание повторов и ручной пересмотр.
- Контракт модели, проверка фактов и расчёт итогового балла.
- Роли, доступ к управлению и выгрузке диагностических записей.
- Досрочное закрытие, ожидание оценок, архив и неизменность итогового рейтинга.
- Создание настроек без замены существующих ключей, смена порта и сетевого адреса.

## Ручная проверка интерфейса

1. Открыть вход, главную, задание, результат, рейтинг и профиль.
2. Проверить «Тон», подпись автора и тёмную тему на каждой странице.
3. В админке открыть главную, список, фильтры, форму задания и поле выбора времени.
4. Проверить контраст статусов, ошибки формы и выделение текущей строки рейтинга.
5. Повторить на узком экране и с навигацией клавиатурой.
6. Проверить первый запуск и повторное обновление на Windows с Docker Desktop.

## Ограничения проверки

Прохождение функциональных тестов не заменяет нагрузочный тест и калибровку реальной модели. Одновременную работу 150 сотрудников, восстановление резервной копии и качество оценок нужно проверять отдельно.

### Проверка 0.5.1 · 22.09.2026

- 16 тестов скриптов прошли. Проверены штатный старт, согласование пароля, повторная проверка и остановка при недоступном локальном администрировании.
- Неинтерактивный `psql` проверен на PGlite по PostgreSQL-протоколу: пароль передан через stdin, команда завершилась без TTY, в системном каталоге сохранён SCRAM-хэш. Проверялся пароль с кавычкой и знаком доллара.
- В CI добавлен сценарий: чистый запуск, контрольная запись в базе, изменение пароля роли, повторный запуск и проверка сохранности записи.
- Полный запуск Docker Desktop/Compose в среде подготовки не выполнялся. CI-сценарий нужно подтвердить после публикации.

### Проверка 0.5.0 · 22.09.2026

- 65 тестов приложения прошли на PGlite через PostgreSQL-протокол; это не заменяет проверку на штатном PostgreSQL 17.
- 10 тестов скриптов настройки прошли, включая сохранение секретов, сетевой адрес и повторную смену порта.
- Django system check, проверка отсутствия новых миграций и сбор статики прошли.
- Проверены HTML-ответы основных страниц сотрудника и администратора, страницы ошибок и CSRF: тема и авторство подключены.
- Синтаксис Python и JavaScript проверен. Проверка CSS в браузере и полный Docker-запуск в среде подготовки недоступны.
- Для проверки на PostgreSQL 17 подготовлен workflow; результат его запуска нужно подтвердить после публикации коммита в GitHub.
