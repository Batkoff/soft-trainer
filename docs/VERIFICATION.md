# Проверки проекта

## Полная проверка через Docker

```bash
python scripts/start.py
docker compose exec -T web python manage.py check
docker compose exec -T web python manage.py makemigrations --check --dry-run
docker compose exec -T web python manage.py test trainer
python -m unittest discover -s scripts -p "test_*.py"
```

Тесты Django используют отдельную тестовую базу PostgreSQL. Не запускайте их с учётной записью production-базы: выполняйте проверки в собственной копии Compose.

В GitHub Actions проверяются сборка образа, запуск на чистой базе, доступность страницы входа и health endpoint, миграции и тесты приложения. Workflow находится в `.github/workflows/ci.yml`; его статус нужно смотреть в Actions конкретного коммита.

## Что покрывают тесты

- Дневной лимит, сохранение ответа, серверный дедлайн и повторная отправка.
- Очередь, временные ошибки API, исчерпание повторов и ручной пересмотр.
- Контракт модели, проверка фактов и расчёт итогового балла.
- Роли, доступ к управлению и выгрузке диагностических записей.
- Досрочное закрытие, ожидание оценок, архив и неизменность итогового рейтинга.
- Создание настроек без замены существующих ключей, смена порта и сетевого адреса.

## Ручная проверка интерфейса

1. Открыть вход, главную, задание, результат, рейтинг и профиль.
2. Проверить «Тон», подпись автора и тёмную тему на каждой странице.
3. В админке открыть главную, список, фильтры, форму задания и поле выбора времени.
4. Проверить контраст статусов, ошибки формы и выделение текущей строки рейтинга.
5. Повторить на узком экране и с навигацией клавиатурой.
6. Проверить первый запуск и повторное обновление на Windows с Docker Desktop.

## Проверка выпуска 0.6.0

Пройдены 75 тестов приложения и 15 тестов скриптов запуска. Также выполнены Django system check, проверка миграций, сбор статики, проверка синтаксиса JavaScript и HTTP-ответов основных страниц.

Автоматические проверки запускаются без реальных API-ключей. HTTP-ответы провайдера подменяются тестовыми данными, чтобы проверять контракт и обработку ошибок без списания средств.

Локальный прогон приложения использует PGlite через PostgreSQL-протокол. Он не заменяет проверку Docker Compose и штатного PostgreSQL 17. Полная сборка, доступность страниц и сохранность базы после смены пароля проверяются workflow GitHub Actions после отправки коммита.

Для приёмки отдельно проверьте реальный API-запрос с ключом выбранного провайдера, первый запуск на Windows и отображение админки в браузере. Нагрузочные испытания на 150 пользователей ещё не проводились.
