# Состояние v0.4.0 · 16 сентября 2026

## Что изменилось

Проверена подготовка к публикации в GitHub: секретный `.env` исключён,
`.env.example` не содержит рабочих ключей, Compose получает пароль БД только
из окружения, а генератор создаёт случайные `SECRET_KEY`, пароль PostgreSQL и
демо-пароль. Для VPS добавлены переменный внешний порт и bootstrap-команда.

Досрочное закрытие конкурса, отправка сохранённых черновиков, ожидание всех
проверок и пересмотров, неизменный итоговый рейтинг и отдельный архив.
Выбор текущего конкурса карточками; будущий старт больше не перекрывает
идущий конкурс по умолчанию. Время — МСК, 00:00:00 по умолчанию, без дробной части.

Диагностика показывает исторический исход запроса и текущее состояние работы
отдельно. Промпт и ответ читаются с переносами. TXT доступен для одной записи,
выбранных записей и отфильтрованного списка. JSON сохранён. Выгрузка требует
права просмотра соответствующего журнала.

Миграция 0005 добавляет closed_at и уточняет имя статуса повторов.
Плановое окончание конкурса остаётся в ends_at. Порядок блокировок там,
где нужны конкурс и работа: сначала конкурс, затем попытка.

## Разбор присланных логов

Пользователь подтвердил реальную оценку Nemotron через OpenRouter, затем
прислал три trace одного неудачного разбора. API вернул готовый JSON; локальная
проверка отвергла цитату «Дополнительные документы сейчас не требуются.»:
в ответе сотрудника не было последней точки. Все три запроса отклонились
по этой причине, а не из-за лимита или баланса.

Валидатор теперь допускает добавленный моделью знак конца предложения
на границе предложения/ответа и возвращает фактическую цитату сотрудника.
Слова, числа, внутреннюю пунктуацию и регистр не подменяет. При настоящем
несовпадении trace указывает stage, поле, fact_id и проблемную цитату.

Старые неудачные работы не перепроверяются автоматически при обновлении.
Администратор может открыть работу и нажать «Повторить проверку».
Это создаёт новый цикл запросов, сохраняя прежние trace.

## Проверка выпуска

Прошли 65 тестов приложения и четыре изолированных теста мастера настройки API.
После последнего изменения блокировок и выбора конкурса повторно прошли
девять тестов жизненного цикла. Django check, проверка полноты миграций,
сбор статики и проверка синтаксиса JavaScript завершились без ошибок.

Автотесты покрывают бизнес-правила, очередь, API-контракт, права и страницы,
включая досрочное закрытие с черновиком, блокировку позднего ответа,
ожидание очереди/пересмотра, повторное закрытие, архив, следующий конкурс,
GET/POST/CSRF, формат времени, отбор TXT по фильтру и выбранным строкам,
защиту выгрузки от руководителя без прав, безопасное отображение HTML из
промпта и регрессию цитат. Реальные API-вызовы заменяются mock-ответами.

Тестовая среда — Django TestCase и PostgreSQL-совместимый PGlite по
PostgreSQL-протоколу в отдельной временной базе. Это не нативный PostgreSQL 17
пользователя. Конкурентные блокировки ещё требуют проверки на штатной базе.

Повторная попытка запуска местного Chromium завершилась SIGSEGV до открытия
страниц. Серверный рендеринг страниц проверен; визуальное выравнивание
карточек и админки нужно подтвердить в браузере пользователя.

## Что подтверждено пользователем раньше

- Docker-демо работает на Windows, доступны тренажёр и админка.
- Таймер продолжает идти при закрытой вкладке.
- Ручной пересмотр работает.
- Реальный разбор от бесплатной модели OpenRouter получен.

## Что ещё не проверено

- Полный новый выпуск в Docker Desktop на Windows и обновление рабочей базы.
- Нагрузка пяти и 150 одновременно активных пользователей.
- Конкурентные транзакции и восстановление после аварии на PostgreSQL 17.
- Восстановление базы из резервной копии.
- Качество и устойчивость модели по эталонам. В присланном разборе модель
  предложила уведомление клиента, которого не было в условиях. Этот пример
  добавлен в бэклог калибровки; исправление точек не решает смысловые ошибки.

## Следующий практический шаг

1. Сделать резервную копию: python scripts/backup_db.py.
2. Заменить исходники, сохранив .env и рабочие данные.
3. Выполнить docker compose up --build -d, обновить страницу с Ctrl+F5.
4. Убедиться, что версия — 0.4.0.
5. Запустить короткий конкурс; открыть задание и сохранить черновик.
6. В карточке конкурса завершить его досрочно; проверить очередь и архив.
7. Запустить следующий конкурс и проверить выбор на главной.
8. Скачать TXT из диагностики; при необходимости повторить старую неудачную работу.

Код, миграции и инструкции включены в архив. API-ключи, рабочая база,
временная тестовая среда и присланные пользователем trace в архив не входят.
