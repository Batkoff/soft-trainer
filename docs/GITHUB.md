# Как отправить изменения в GitHub

Все команды выполняются из папки `soft-trainer`, где лежит `compose.yaml`.

## Применить выпуск, полученный патчем

Сначала проверьте состояние:

```bash
git status --short
```

Если есть ваши изменения в исходниках, сохраните их отдельным коммитом до применения патча. Скачанный `.patch` игнорируется и не должен попадать в коммит.

Для обновления с версии 0.5.2:

```bash
git am ./ton-v0.6.0.patch
python scripts/start.py
```

`git am` сам создаёт коммиты из патча. Повторно выполнять `git commit` для них не нужно. Если патч не применился, остановитесь и прочитайте ошибку. Отменить незавершённое применение можно командой `git am --abort`; не удаляйте базу и `.env`.

## Отправить текущую ветку

```bash
git log -5 --oneline
git push -u origin HEAD
```

На странице репозитория откройте **Compare & pull request**, выберите целевую ветку `develop`, проверьте изменения и создайте Pull Request. После успешных проверок нажмите **Merge pull request**. Файлы README и `docs/GETTING_STARTED.md` появятся в основной ветке после слияния.

## Если меняли файлы сами

```bash
git status --short
git add -A
git diff --cached --stat
git diff --cached
git commit -m "Улучшить запуск и настройки тренажёра"
git push -u origin HEAD
```

Перед коммитом просмотрите добавляемый текст. `.gitignore` исключает `.env`, начальные пароли, дампы, журналы, архивы, патчи, локальные окружения и сгенерированную статику. `.env.example` содержит только названия настроек и пустые поля секретов.

Проверить, не отслеживаются ли локальные секреты:

```bash
git ls-files .env .demo-credentials.txt
git check-ignore .env .demo-credentials.txt ton-v0.6.0.patch
```

Первая команда должна ничего не вывести. Вторая показывает игнорируемые пути. Если секрет уже был закоммичен ранее, одного `.gitignore` недостаточно: уберите файл из индекса и замените раскрытый ключ у провайдера.

## Сохранить промежуточную работу

Делайте небольшой коммит после завершённого изменения и отправляйте ветку в GitHub. Для отдельной копии исходников:

```bash
git archive --format=zip --output=ton-checkpoint.zip HEAD
```

Архив содержит закоммиченные файлы. База, ключи и незакоммиченные правки в него не входят. Резервное копирование данных описано в [VPS.md](VPS.md).
