# Как запустить «Тон» на своём компьютере

Это инструкция для первого запуска. Разбираться в Django, PostgreSQL и настройке серверов не нужно: всё необходимое для приложения запускается через Docker.

## 1. Что установить

- **Docker Desktop:** [официальная установка](https://docs.docker.com/desktop/). На Windows выберите Linux containers и используйте WSL 2. Если установщик просит перезагрузку — перезагрузите компьютер.
- **Python 3.10 или новее:** [python.org](https://www.python.org/downloads/). В установщике для Windows отметьте **Add python.exe to PATH**.
- **Git:** [git-scm.com](https://git-scm.com/downloads). Нужен, чтобы скачать проект и получать обновления. Вместо Git для первого знакомства можно скачать ZIP.

Откройте Docker Desktop и дождитесь запуска движка. Одной установки недостаточно: приложение Docker должно работать.

В PowerShell выполните по очереди:

```powershell
python --version
docker compose version
docker info
```

Если `python` не найден, попробуйте `py -3 --version`. В дальнейших командах можно заменить `python` на `py -3`. На macOS и Linux обычно используется `python3`.

## 2. Скачать проект

На Windows откройте PowerShell и выполните:

```powershell
cd $HOME
git clone https://github.com/Batkoff/soft-trainer.git
cd soft-trainer
```

Получится отдельная папка проекта в вашей домашней папке. Для первого запуска удобнее обычная локальная папка, без синхронизации OneDrive.

Если Git не установлен: на странице репозитория нажмите **Code → Download ZIP**, распакуйте архив, откройте получившуюся папку. В ней должны лежать `compose.yaml`, `README.md` и `start-demo.bat`. Откройте терминал именно в этой папке.

Не запускайте проект прямо из ZIP и не переносите `.env` с чужого компьютера: для своей копии создаются свои ключи и пароли.

## 3. Запустить

Самый простой способ на Windows — дважды нажать **start-demo.bat**.

Либо в терминале из папки проекта:

```powershell
python scripts/start.py
```

Скрипт проверит Docker, создаст настройки, соберёт приложение и дождётся готовности. Первый запуск дольше повторных: Docker скачивает Python, PostgreSQL и Caddy. Не закрывайте окно, пока идёт сборка.

Когда появится **«Тон готов»**, откройте:

**http://localhost:8080**

В адресе нужен `http`, не `https`. `localhost` — это компьютер, на котором запущен проект.

Если предпочитаете команды вручную:

```powershell
python scripts/prepare_demo.py
docker compose up --build --wait --wait-timeout 180
```

В Git Bash пишите пути с обычным слешем: `scripts/prepare_demo.py`. Обратный слеш в команде `python scripts\prepare_demo.py` может исчезнуть, и Python будет искать несуществующий `scriptsprepare_demo.py`.

## 4. Войти

В папке проекта появился файл **`.demo-credentials.txt`**. Откройте его Блокнотом: там начальный пароль.

| Аккаунт | Логин | Для чего |
|---|---|---|
| Администратор | `admin` | Настройки, задания, конкурсы, диагностика |
| Сотрудники | `demo1` — `demo5` | Прохождение тренировки |

Начальный пароль общий для этих учебных аккаунтов. Для реального пилота создайте личные учётные записи. Если пароль уже меняли в админке, используйте новый: повторный запуск не сбрасывает его.

Для знакомства войдите как `admin`, откройте **Песочницу**, выберите задание и отправьте ответ. По умолчанию включён тестовый оценщик: он проверяет работу механики, а не качество текста. API и оплата для такого запуска не нужны.

Чтобы получать настоящий разбор текста, следуйте [инструкции подключения модели](AI_SETUP.md).

## 5. Остановить и запустить снова

Остановить:

```powershell
docker compose stop
```

Запустить снова:

```powershell
python scripts/start.py
```

Данные хранятся в отдельном томе PostgreSQL и переживают перезапуск контейнеров. Команда `docker compose down` тоже оставляет этот том. **Не добавляйте `-v`: этот флаг удаляет данные.**

## 6. Обновить проект

Из папки проекта:

```powershell
git pull --ff-only
python scripts/start.py
```

Скрипт сохранит ваши ключи и пароли. Контейнер `init` применит новые миграции и обновит стили. Если браузер показывает старый дизайн, нажмите **Ctrl+F5**.

Если Git сообщает о ваших локальных изменениях, не используйте `reset --hard`: сначала сохраните свои правки. Если скачивали ZIP, распакуйте новый выпуск отдельно, перенесите только свой `.env` и `.demo-credentials.txt`, затем запустите из новой папки. Проект Compose остаётся `soft-trainer`, поэтому на том же Docker-хосте используется прежний том базы.

## Если не запустилось

| Что видно | Что проверить |
|---|---|
| `docker` не найден | Установите Docker Desktop, откройте новый терминал |
| `Cannot connect to the Docker daemon`, `dockerDesktopLinuxEngine` | Откройте Docker Desktop, дождитесь запуска; проверьте режим Linux containers |
| `python` не найден или открылся Microsoft Store | Используйте `py -3`; либо установите Python и добавьте его в PATH |
| `no configuration file provided` | Терминал открыт не в папке проекта; перейдите туда, где `compose.yaml` |
| `port is already allocated`, `address already in use` | Запустите `python scripts/start.py --port 8081`, затем откройте `http://localhost:8081` |
| Ошибка скачивания `python`, `postgres`, `caddy` или пакетов Python | Проверьте доступ Docker к Docker Hub и PyPI, настройки сети/прокси. Затем повторите запуск |
| `init` завершился с ошибкой | Выполните `docker compose logs --tail=100 init`; именно он запускает миграции и создаёт учебные данные |
| `init` имеет статус `Exited (0)` | Это нормально: он выполнил свою работу. `web`, `worker` и `proxy` должны продолжать работать |
| `400 Bad Request` с другого компьютера | Адрес не разрешён Django. Используйте запуск с `--host`, как в следующем разделе |
| `403 CSRF verification failed` | Открытый адрес должен быть в `CSRF_TRUSTED_ORIGINS`, включая протокол и порт; после изменения `.env` повторите запуск |
| `Cannot GET /`, чужая страница | Убедитесь, что это `http://localhost:8080`, а не другой порт или старый туннель. Проверьте `/health/` и `docker compose ps -a` |
| `password authentication failed` у PostgreSQL | Пароль `.env` должен соответствовать уже существующей базе. Верните исходный `.env`, не удаляйте том базы ради исправления |
| Страница открывается, ответ остаётся в очереди | Проверьте `docker compose logs --tail=100 worker`; для реальной оценки также откройте «Диагностику API» |

Общая проверка:

```powershell
docker compose ps -a
docker compose logs --tail=100 init web worker proxy
```

Сохранить эти логи в файл:

```powershell
docker compose logs --no-color --tail=300 init web worker proxy > startup-log.txt
```

Если падает именно **сборка**, её вывод не появляется в логах контейнера. В PowerShell сохраните его отдельно:

```powershell
docker compose --progress plain build 2>&1 | Tee-Object build-log.txt
```

Не отправляйте `.env`, `.demo-credentials.txt` или вывод полного `docker compose config`: там могут быть секреты.

## Доступ с другого компьютера в вашей сети

На компьютере, где запущен Docker, найдите локальный IPv4 через `ipconfig`. Например, это `192.168.1.20`.

```powershell
python scripts/start.py --host 192.168.1.20
```

На втором компьютере откройте `http://192.168.1.20:8080`. Оба компьютера должны быть в одной сети; входящее соединение на этот порт должно быть разрешено брандмауэром.

Скрипт добавит адрес в разрешённые хосты и CSRF origins, а Docker начнёт слушать сетевые интерфейсы. `localhost` друга не ведёт на ваш компьютер. Для доступа через интернет нужен сервер или настроенный туннель.

## Резервная копия

```powershell
python scripts/backup_db.py
```

Копия базы появится в `backups/`. Храните её отдельно от компьютера вместе с защищённой копией `.env`. Ключи и резервные копии не входят в Git.
