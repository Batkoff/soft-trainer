# Устройство проекта

Один Django-проект и одна PostgreSQL. Caddy раздаёт статику и передаёт HTTP-запросы Gunicorn. Отдельный worker обрабатывает задания Procrastinate; очередь находится в той же базе. HTMX подключён локально, сборка JavaScript не требуется.

## Модули

| Путь | Назначение |
| --- | --- |
| `trainer/models.py` | Задания, конкурсы, попытки, результаты и настройки |
| `trainer/services.py` | Правила конкурсов, дедлайнов и пересмотра |
| `trainer/tasks.py` | Очередь проверки и восстановление зависших заданий |
| `trainer/evaluation_http.py` | Запрос к API и проверка структуры ответа |
| `trainer/evaluation_profiles.py` | Профиль модели, закрепляемый за конкурсом |
| `trainer/ai_configuration.py` | Чтение и расшифровка ключей |
| `trainer/ai_views.py` | Страница настройки подключения |
| `trainer/admin.py`, `config/admin.py` | Управление и навигация администратора |
| `templates`, `static` | HTML, стили и поведение интерфейса |
| `scripts/start.py` | Подготовка и запуск Docker, проверка базы и доступа |

## Данные и очередь

Попытка сохраняет снимок задания и рубрики. Редактирование задания не переписывает уже выданные условия. Изменения попыток выполняются транзакционно с блокировками строк. Уникальные дневные слоты и идемпотентная отправка защищают лимит от повторных кликов.

Дедлайн считается сервером. Закрытие вкладки не останавливает таймер. По истечении срока оценивается сохранённый до дедлайна черновик. Пустой ответ получает ноль локально, без вызова API.

Проверка не удерживает HTTP-запрос сотрудника: worker сохраняет результат, страница получает новый статус. Временные ошибки повторяются ограниченное число раз. После исчерпания повторов администратор может повторить проверку. Неопределённый hard-вердикт отправляется на пересмотр.

## Оценка

Реальный оценщик поддерживает OpenAI и OpenRouter. Он запрашивает структурированный ответ, проверяет обязательные факты и пять soft-навыков. Итог вычисляет приложение по весам рубрики; существенное нарушение hard-информации даёт ноль. Первоначальный ответ модели сохраняется отдельно от ручного пересмотра.

Тестовый оценщик доступен только автоматическим тестам через явное переопределение настройки. В рабочем режиме старый демонстрационный профиль не выдаёт баллы.

При запуске конкурса закрепляется текущая модель. Новая настройка применяется к новым конкурсам и песочнице, а существующие попытки сохраняют свой профиль. Ключи читаются worker из базы при запросе. Они зашифрованы Fernet с ключом, производным от `SECRET_KEY`; в профиль, журнал действий и HTML секрет не попадает. При отсутствии ключа в базе поддерживается значение окружения.

## Конкурсы

Стартовый набор создаёт черновик с учебными заданиями и участниками. Администратор проверяет условия и запускает конкурс. Досрочное закрытие прекращает приём новых ответов. Фиксация итогов сохраняет таблицу результатов; архив не пересчитывается от последующих изменений.

Набор заданий на день одинаков для участников. При небольшом банке задания могут повторяться в разные дни. Песочница исключена из рейтинга. Призы отображаются в интерфейсе; автоматической выплаты T-Money нет.

## Доступ и диагностика

Сотрудник видит свои задания и результаты. Руководители имеют ограниченные права управления, суперпользователь управляет подключением и конкурсами. Ограничение руководителя только своей группой пока не реализовано.

Диагностика содержит запрос, ответ API, длительность, токены и ошибки. Она доступна по разрешениям администратора и экспортируется в текст. События изменения настроек сохраняют провайдера и модель, но не ключ.

## Развёртывание

Compose запускает `db`, одноразовый `init`, `web`, `worker` и `proxy`. Сайт по умолчанию привязан к localhost. Для VPS настраиваются домен, HTTPS и разрешённые адреса. База не публикует порт наружу.

Резервная копия PostgreSQL и отдельная копия `.env` нужны для полного восстановления. Исходники не содержат пользовательских данных и ключей.
