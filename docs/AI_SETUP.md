# Подключение нейросети

1. Запустите проект и войдите под `admin`.
2. Откройте **Управление → Нейросеть** или `/settings/ai/`.
3. Выберите провайдера и модель. Для модели вне списка выберите «Другая модель» и вставьте её идентификатор из кабинета провайдера.
4. Вставьте API-ключ и нажмите **Сохранить подключение**.
5. Перейдите в песочницу, откройте задание и отправьте ответ. Результат появится после обработки очередью.

Перезапуск Docker не нужен. Пустое поле ключа сохраняет ранее введённый ключ выбранного провайдера. Чтобы заменить ключ, вставьте новый и сохраните. Для OpenAI и OpenRouter ключи хранятся отдельно.

Бесплатный вариант OpenRouter есть в списке моделей. Его доступность, квоты и поддержка формата ответа определяются провайдером. При отказе API сервис покажет ошибку или назначит повтор; вымышленных баллов не будет. Подписка ChatGPT не является API-ключом.

## Конкурс

После проверки в песочнице откройте **Конкурсы**. Стартовый конкурс уже содержит задания и учебных участников, но остаётся черновиком. Проверьте даты и участников, затем запустите его действием в админке.

При запуске закрепляется текущая модель. Изменение настроек подключения не меняет модель действующего конкурса. Старый конкурс с тестовым оценщиком нельзя продолжать с реальными оценками: создайте новый. Прежние результаты сохраняются.

## Если оценка не пришла

Откройте **Управление → Запросы к нейросети**. В записи есть запрос, ответ провайдера, ошибка, токены и время выполнения. Скачайте текстовый журнал нужной попытки. Ключ не включается в журнал.

- Временный сбой: очередь назначает повтор.
- Попытки исчерпаны: после исправления подключения повторите проверку из интерфейса.
- Спорный результат: администратор пересматривает hard-вердикт и soft-оценки с указанием причины.

## Хранение настроек

Введённые через сайт ключи зашифрованы в PostgreSQL с использованием `SECRET_KEY`. Резервная копия базы и исходный `.env` нужны вместе. При потере `SECRET_KEY` потребуется повторно ввести ключи; старые ответы не теряются.

Для серверной установки поддерживаются `OPENAI_API_KEY` и `OPENROUTER_API_KEY` из окружения. Ключ, сохранённый через сайт, имеет приоритет. Настройки доступны только суперпользователю; руководители и сотрудники их не видят.
