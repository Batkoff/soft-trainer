# Размещение «Тона» на VPS

Тот же Docker Compose используется на компьютере и сервере. PostgreSQL не публикует порт наружу; браузер обращается к Caddy, который передаёт запросы приложению. Данные базы и HTTPS-сертификаты хранятся в отдельных томах.

## Подготовка

Нужны Linux-сервер, Git, Python 3.10+ и Docker Engine с Compose v2. Учётная запись должна иметь право запускать Docker. Начните с небольшого пилота; требуемые ресурсы для 150 одновременных пользователей определяются нагрузочным тестом, а не количеством открытых вкладок.

```bash
git clone https://github.com/Batkoff/soft-trainer.git
cd soft-trainer
python3 scripts/prepare_demo.py
```

Для временной проверки по IP:

```bash
python3 scripts/start.py --host 203.0.113.10
```

Замените пример на адрес своего VPS и разрешите входящий TCP 8080 в сетевых правилах провайдера и брандмауэре. Откройте `http://ВАШ_IP:8080`. Это HTTP-проверка: для постоянного входа пользователей настройте HTTPS.

## Домен и HTTPS

1. Направьте A-запись домена на IPv4 сервера. Если есть AAAA-запись, IPv6 тоже должен вести на этот сервер.
2. Разрешите входящие TCP **80** и **443**. Эти порты должны быть свободны.
3. В `.env` замените параметры ниже, оставив свои пароли и API-ключи без изменений:

```dotenv
SITE_ADDRESS=ton.example.org
HTTP_BIND=0.0.0.0
HTTP_PORT=80
HTTPS_PORT=443
ALLOWED_HOSTS=ton.example.org,localhost,127.0.0.1,[::1]
CSRF_TRUSTED_ORIGINS=https://ton.example.org
SECURE_COOKIES=1
DEBUG=0
```

Замените `ton.example.org` на свой домен. В `SITE_ADDRESS` нужен только домен, без протокола и пути. В `CSRF_TRUSTED_ORIGINS` — полный origin с `https://`.

4. Запустите:

```bash
python3 scripts/start.py
docker compose logs --tail=100 proxy
```

Caddy запросит сертификат и включит HTTPS; HTTP будет перенаправляться на HTTPS. Выдача сертификата требует корректных DNS-записей, доступности портов и доступа к удостоверяющему центру. Готовность контейнера не подтверждает выдачу сертификата: проверьте журнал Caddy и откройте `https://ВАШ_ДОМЕН/health/`.

## Перед выдачей доступа

- Создайте личные учётные записи. Смените начальный пароль администратора, отключите ненужные демо-аккаунты.
- Создайте свой конкурс с нужным оценщиком: существующий демонстрационный конкурс остаётся тестовым.
- Проверьте отправку ответа, работу очереди, пересмотр и закрытие конкурса.
- Сделайте резервную копию и проверьте восстановление в отдельной среде.

## Обновление и диагностика

```bash
python3 scripts/backup_db.py
git pull --ff-only
python3 scripts/start.py
docker compose ps -a
```

`init` со статусом `Exited (0)` — штатное состояние. Его журнал содержит результат миграций и сбора статики. Старые секреты, учётные записи и ответы обновление не сбрасывает.

```bash
docker compose logs --tail=100 init web worker proxy
```

Не удаляйте том `database` и не выполняйте `docker compose down -v` при обычном обновлении. Копируйте `backups/` на отдельный носитель; папка внутри VPS не защищает от потери самого сервера.

Если перед приложением уже работает другой reverse proxy или туннель, отдельно согласуйте адрес сайта, CSRF origins и передачу протокола. Эта инструкция описывает прямое подключение к Caddy проекта.
