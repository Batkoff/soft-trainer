# Практика — MLP тренажёра поддержки · v0.4.0

Внутренний тренажёр поддержки: задания, три минуты на ответ, фоновая проверка,
рейтинг и управление. В этой версии можно включить реальную оценку через
OpenAI или OpenRouter. По умолчанию остаётся бесплатный демонстрационный режим.

## Что уже реализовано

- Django + PostgreSQL; интерфейс на Django Templates, HTMX и небольшом JavaScript.
- Вход, пять учебных сотрудников и администратор.
- Конкурсы, дневной лимит, трёхминутный таймер, автосохранение черновика.
- Очередь Procrastinate, демонстрационный и реальный API-оценщики, разбор и рейтинг.
- Админка заданий и конкурсов, аналитика, песочница, калибратор и пересмотр оценок.
- Пересмотр пяти soft skills с сохранением исходного результата.
- Простой выбор ролей, профиль с ником и готовыми аватарами, встроенный гайд.
- Технические JSON-логи, журнал действий, версия интерфейса и история изменений.
- Диагностика каждой проверки: полный prompt/ответ модели, токены, время и ошибки
  в админке с выгрузкой TXT/JSON; API-ключ в неё не записывается.
- Призовой фонд по умолчанию 100 / 70 / 50 T-Money; рейтинг закрывается автоматически
  после окончания конкурса, если все попытки проверены.
- Досрочное завершение, отдельный архив результатов, переключение конкурсов карточками.

Статус проверки и ограничения: [docs/VERIFICATION.md](docs/VERIFICATION.md).
Схема и объяснение бизнес-правил: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

История выпусков: [CHANGELOG.md](CHANGELOG.md). Следующие задачи: [BACKLOG.md](BACKLOG.md).
В интерфейсе — номер версии внизу и страница «Что нового». Учебные сценарии вымышлены.
Живой API-запрос при подготовке выпуска не выполнялся: ключ задаёт владелец проекта.

## Подготовка репозитория для GitHub

В репозиторий публикуется только исходный код. Файлы `.env`, `.demo-credentials.txt`,
резервные копии, логи, архивы и скомпилированная статика исключены через `.gitignore`.
Ключи OpenAI/OpenRouter в исходниках отсутствуют. `.env.example` — только шаблон.

После клонирования новый `.env` создаётся безопасно:

```bash
python scripts/prepare_demo.py
# или на Linux/VPS:
python3 scripts/bootstrap_env.py
```

Оба скрипта не перезаписывают существующий `.env`. Для реального оценщика ключ
вводится после этого командой `python scripts/configure_ai.py` или добавляется
администратором вручную на сервере. Сам `.env` в GitHub никогда не загружайте.

## Запуск через Docker

Нужны Python 3.10+ для генератора настроек и запущенный Docker с Compose.
Само приложение работает на Python 3.12 внутри контейнера. В Windows можно
использовать `start-demo.bat`. В Git Bash в командах ниже используются `/`.

```bash
python scripts/prepare_demo.py
docker compose up --build -d
```

Открыть http://localhost:8080. Логины и сгенерированный пароль будут в `.demo-credentials.txt`.

```bash
docker compose logs -f web worker
docker compose stop
```

Данные сохраняются в именованном томе `database`. Команда `docker compose down -v` удаляет этот том — для обычной остановки её использовать не следует.

Чтобы запустить снова: `docker compose up -d`. Чтобы применить новый код:
`docker compose up --build -d`. Миграции выполняет отдельный сервис `init`.

## Запуск на VPS

Подойдёт Ubuntu 24.04, минимум 2 ГБ RAM, 1–2 vCPU и 30 ГБ диска. На VPS нужен
Docker Engine с Compose plugin и открытый TCP-порт 8080. Домен и HTTPS можно
добавить позже; на первом этапе сайт открывается как `http://IP_VPS:8080`.

```bash
git clone https://github.com/ВАШ_АККАУНТ/soft-trainer.git
cd soft-trainer
python3 scripts/bootstrap_env.py
docker compose up --build -d
docker compose ps
curl http://127.0.0.1:8080/health/
```

Можно выполнить то же одной командой: `bash scripts/deploy_vps.sh`.
Compose сам запускает PostgreSQL, миграции, web, worker и Caddy. Данные лежат
в именованных Docker volumes и переживают перезапуск контейнеров.

Для внешнего IP используется `HTTP_BIND=0.0.0.0` и `HTTP_PORT=8080`. Если перед
контейнером будет внешний Nginx/Caddy, задайте `HTTP_BIND=127.0.0.1`, а наружу
выставьте только внешний прокси. Не публикуйте PostgreSQL-порт.

Перед обновлением рабочей базы:

```bash
python3 scripts/backup_db.py
git pull
docker compose up --build -d
docker compose logs --tail=100 init web worker
```

Не используйте `docker compose down -v`: команда удаляет базу и результаты.

## Обновление существующего проекта до 0.4.0

1. В прежней папке проекта выполнить `python scripts/backup_db.py`.
2. Распаковать содержимое новой папки `soft-trainer` поверх прежней с заменой
   исходников. Оставить свои `.env`, `.demo-credentials.txt` и `backups` на месте:
   они не включены в архив. Не создавать вложенную папку `soft-trainer/soft-trainer`.
3. Выполнить `docker compose up --build -d`. Сервис `init` применит недостающие
   миграции, включая `0005` — досрочное закрытие и понятный статус повторов.
4. Нажать Ctrl+F5. Внизу тренажёра и админки должна быть версия **0.4.0**.
5. Если запускается старая версия, проверить `docker compose logs --tail=80 init`
   и `docker compose ps -a`. После исправления ошибки повторить сборку.

Используйте прежнюю папку и прежний Docker-том. Рабочие данные мигрируются,
история оценок сохраняется. Обновление не требует удаления базы.

## Проверить короткий конкурс и завершить досрочно

1. Админка → Конкурсы → Добавить. Укажите текущую дату и время старта,
   окончание через пять минут. Все сроки — МСК; пустое время означает 00:00:00.
2. Выберите задания и участников (включая `admin`), сохраните и запустите
   действием «Запустить выбранные конкурсы». При будущем старте задания
   откроются в назначенное время без дополнительного действия.
3. Пройдите задание. В карточке конкурса нажмите «Завершить досрочно» и подтвердите.
   Приём ответов прекратится; уже сохранённые черновики отправятся на проверку.
4. Если все работы проверены, итоги фиксируются сразу. Иначе конкурс показывает
   «Подводим итоги». Очередь должна закончить работу, спорные оценки нужно
   пересмотреть. Затем worker зафиксирует рейтинг в течение минуты; можно
   также нажать «Проверить и зафиксировать итоги» в карточке.
5. Итоговая таблица остаётся в **Рейтинг → Завершённые конкурсы**. На главной
   автоматически выбирается следующий доступный конкурс. Новый конкурс
   администратор создаёт сам: произвольные черновики автоматически не запускаются.

Досрочное закрытие не меняет плановую дату окончания в истории. Законченный
конкурс нельзя возобновить или пересмотреть его итоговые оценки.

## Скачать логи для разбора ошибки

- Админка → **Диагностика API**: запросы к оценщику, промпт, полный ответ,
  длительность, токены и точная причина ошибки. Зелёный — успешно; жёлтый —
  после сбоя был назначен повтор; красный — запрос завершился ошибкой.
- **Состояние работы сейчас** показывает, ждёт ли она очереди, уже проверена
  или требует администратора. Статус старого запроса не переписывается.
- В карточке или списке есть **Скачать .txt**; также сохранён JSON. Кнопка
  **Скачать этот список .txt** учитывает фильтр и поиск. Можно отметить нужные
  строки и выбрать действие скачивания. Журнал действий выгружается так же;
  для событий оценки в файл включается связанный prompt/ответ.
- Старую работу, остановленную ошибкой цитаты, после обновления откройте
  из диагностики и нажмите **Повторить проверку**. История останется на месте;
  обновление само не тратит запросы на повтор старых работ.

Файл UTF-8 открывается в Блокноте Windows. API-ключи и HTTP-заголовки не
включаются; учебные тексты сотрудника и модели включаются для диагностики.

## Подключить реальную оценку

Нужен API-ключ выбранного сервиса и доступ к модели. Подписка ChatGPT и API
оплачиваются отдельно — [справка OpenAI](https://help.openai.com/en/articles/9039756).

Самый короткий путь в Git Bash или PowerShell, из папки проекта:

```bash
python scripts/configure_ai.py
docker compose up --build -d
```

Мастер предложит OpenAI, OpenRouter или тестовый режим. API-ключ вводится
в локальном терминале скрыто и сохраняется в `.env`. Мастер не делает
запросов и не проверяет баланс. Затем войдите как `admin`, откройте
**Песочница → Реальная оценка нейросетью**, выберите задание и отправьте ответ.
Появятся проверенные факты, оценки навыков, пояснения и вариант ответа.

### Бесплатная проверка через OpenRouter

Для пробного запуска подготовлен профиль **NVIDIA Nemotron 3 Super (free)**.
По состоянию на 16.09.2026 бесплатный endpoint есть в каталоге, цена входа и
выхода — 0, заявлена поддержка `response_format` / Structured Outputs,
`temperature` и отключаемого reasoning. Это проверка метаданных API;
живой запрос с ключом пользователя при подготовке выпуска не выполнялся.

1. Откройте свой `.env`: `notepad .env`.
2. Замените существующие строки, сохранив свой ключ:

```dotenv
EVALUATOR_BACKEND=openrouter
EVALUATOR_MODEL=nvidia/nemotron-3-super-120b-a12b:free
OPENROUTER_API_KEY=ваш-ключ-OpenRouter
```

3. После обновления исходников выполните `docker compose up --build -d`.
4. Откройте **Песочница → Реальная оценка нейросетью** и создайте новую попытку.
   Уже созданные попытки сохраняют прежнюю модель. Старый демо-конкурс остаётся
   тестовым; для рейтинга с новой моделью нужен новый конкурс.

Этот профиль отключает reasoning через `reasoning.enabled=false`, оставляя
2400 токенов на JSON-разбор. Сам параметр сохраняется в рубрике конкурса.
Строгая схема и проверка фактов остаются включены. Суффикс `:free` обязателен:
это отдельный бесплатный вариант модели. Платные fallback-модели не задаются.

На бесплатном тарифе заявлены 50 запросов в сутки на аккаунт. Пять человек
по пять заданий — 25 успешных запросов, но повторы, калибровка и другие обращения
к API тоже расходуют доступную квоту. Возможны отдельные ограничения частоты,
перегрузка провайдера и 429. Нулевой баланс подходит для бесплатных моделей;
отрицательный баланс и ограничения ключа могут приводить к 402 даже для них.

Доступность бесплатного endpoint не гарантируется, качество русскоязычной
оценки ещё нужно проверить на эталонах. NVIDIA предупреждает о журналировании
в бесплатном endpoint: используйте вымышленные задания и ответы, без
персональных данных и конфиденциальной информации.

Источники: [модель и условия бесплатного endpoint](https://openrouter.ai/nvidia/nemotron-3-super-120b-a12b:free),
[бесплатный тариф](https://openrouter.ai/pricing),
[лимиты и ошибки](https://openrouter.ai/docs/api_reference/limits),
[параметры reasoning и бюджет ответа](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens),
[метаданные endpoint](https://openrouter.ai/api/v1/models/nvidia/nemotron-3-super-120b-a12b:free/endpoints).

### Если после выбора 1 или 2 ничего не видно

На шаге ввода ключа используется скрытый ввод Python. На Windows некоторые
терминалы Git Bash несовместимы с таким вводом. В 0.3.1 мастер проверяет
Windows-консоль заранее и выводит инструкцию вместо перехода к скрытому вводу.
Сам Windows-сценарий ещё требует подтверждения на компьютере пользователя.

В старом мастере нажмите Ctrl+C. Выполните `notepad .env`, замените параметры
провайдера по примеру ниже, сохраните файл и выполните `docker compose up --build -d`.
Заменяйте существующие строки: не добавляйте второй EVALUATOR_BACKEND или API-ключ.
Остальные строки оставьте как есть. Альтернатива — запустить мастер из PowerShell.

Если приглашение к вводу ключа видно, отсутствие символов и звёздочек при
наборе нормально: вставьте ключ и нажмите Enter.

То же вручную: добавить в свой `.env` один из вариантов.

```dotenv
# OpenAI напрямую
EVALUATOR_BACKEND=openai
EVALUATOR_MODEL=gpt-4.1-mini-2025-04-14
OPENAI_API_KEY=ваш-ключ
```

```dotenv
# OpenRouter — агрегатор; это отдельный ключ его сервиса
EVALUATOR_BACKEND=openrouter
EVALUATOR_MODEL=openai/gpt-4.1-mini
OPENROUTER_API_KEY=ваш-ключ
```

Пустой `EVALUATOR_MODEL` выбирает указанные выше модели по умолчанию.
Начальная модель — GPT-4.1 mini. Адаптер использует Chat Completions,
строгий `json_schema` и `temperature=0`: другая модель должна поддерживать
эти параметры. У OpenRouter требуется поддержка параметров, автоматическое
переключение между провайдерами отключено. Это не гарантирует неизменную
внутреннюю версию модели за псевдонимом: сохраняются запрошенная модель и
имя, вернувшееся в ответе API. Для конкурса закрепляйте доступный снимок модели.

**Старый демо-конкурс остаётся тестовым.** После подключения API создайте
новый конкурс: его профиль зафиксирует провайдера, модель и версию промпта.
Это не смешивает тестовые и реальные баллы в одном соревновании.
Песочница позволяет сразу проверить реальную модель без нового конкурса.
Симуляции ошибок в песочнице всегда бесплатны и API не вызывают.

Обычно одна проверка — один запрос. При временной сетевой ошибке, 429,
ошибке 5xx или некорректном разборе очередь делает до трёх попыток суммарно.
Неправильный ключ, отказ модели или исчерпанный баланс сразу требуют
администратора. При сбое балл не начисляется и ответ не теряется.
Повторный запрос может также учитываться в расходах провайдера.

При существенном нарушении обязательных фактов — 0; soft-разбор остаётся.
При неоднозначном hard-вердикте — ручная проверка без выставленного балла.
Общий балл вычисляется в приложении по весам пяти навыков, а не берётся
из произвольного числа, названного моделью. Пустой просроченный ответ
обрабатывается локально без расходов API.

API получает только учебное задание и ответ. Имя, логин и внутренние ID
сотрудника в запрос не включаются. На первом пилоте используйте вымышленные
примеры. Ключи и тексты запросов/ответов не пишутся в технические логи;
сам разбор хранится в базе для истории и пересмотра. Для OpenAI задано
`store=false`; это не является обещанием отсутствия хранения данных у провайдера.

В логах `worker` есть провайдер, модель, длительность и токены ответа API.
Временные и постоянные ошибки показываются администратору без сырых ответов
провайдера. Лимиты запросов задаются API-аккаунтом; они не зависят от числа
открытых вкладок. Начальная очередь выполняет до двух задач одновременно.
Это настройка для малого пилота, нагрузка 150 пользователей ещё не измерялась.

Правила оценки заданы в `trainer/evaluation_prompt.py`, контракт и проверка
формата — в `trainer/evaluation_http.py`. Дообучение не требуется для первого
подключения. Следующий этап — калибровка по человеческим эталонам; стабильность
и точность оценок пока не подтверждены. `temperature=0` снижает случайность,
но не делает модель абсолютно детерминированной.

Документация интеграции: [Structured Outputs OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs),
[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini),
[Structured Outputs OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs).

Сервис слушает только локальный адрес компьютера. Общий доступ для пяти
участников потребует размещения на доступном им хосте и настройки домена,
HTTPS, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` и `SECURE_COOKIES=1`.

## Первое знакомство

1. Войти как `demo1`. На главной начать задание, написать ответ и отправить.
2. Дождаться фоновой проверки. Обычная тестовая оценка — 80; качество текста
   в демонстрационном режиме она не измеряет. Посмотреть результат и рейтинг.
3. Войти как `admin`. В песочнице проверить hard-ошибку, временный сбой и
   постоянный сбой. Песочница не влияет на рейтинг.
4. В админке создать черновик задания, заполнить обязательные факты и
   опубликовать действием в списке. Для правки опубликованного задания
   нажать в карточке «Редактировать новую версию».
5. Создать конкурс: сроки, участники, опубликованные задания, призы.
   После запуска условия замораживаются. Демо-конкурс уже создан.
6. Спорный результат открыть из аналитики и пересмотреть hard-вердикт и пять
   soft skills с указанием причины.
   В калибраторе можно сохранить пример с ожидаемой оценкой и запустить его.
7. Для руководителя открыть «Пользователи» → «Добавить», выбрать роль
   «Руководитель». Он видит все работы пилота, может пересматривать оценки,
   но не может управлять пользователями, заданиями и конкурсами.
8. «Как пользоваться» в меню содержит подробный гайд. «Мой профиль» сохраняет
   ник и выбранный аватар; смена логина и пароля в профиле пока — заглушки.

`seed_demo` добавляет администратора в демо-конкурс. В создаваемые вручную
конкурсы добавляйте его до запуска. «Последний вход» в карточке пользователя — только для чтения.

Повторный `seed_demo` не сбрасывает пароли и результаты. Демо-логины доступны
только потому, что запуск явно создаёт эти учебные аккаунты. Перед общим
использованием администратор создаёт личные учётные записи и пароли.

## Разработка

В Docker:

```bash
docker compose exec web python manage.py test trainer
docker compose logs -f worker
```

Тесты используют отдельную тестовую базу Django. Учётная запись должна иметь
право создавать её; у локального Docker-демо такое право есть.

Дополнительный запуск без Docker для обычного пользователя Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python scripts/run_local.py
```

Он использует `pgserver`, держит данные в `.data/postgres` и открывает сервис
на http://127.0.0.1:8000. Этот способ в текущей среде не проверен.

## Сохранение проекта

Архив содержит исходный код, миграции и инструкции. В него не входят пароли,
рабочая база и зависимости среды. Сохраняйте `.env` отдельно от общего кода.

Для сохранения ответов, результатов, пользователей и очереди Docker-демо:

```bash
python scripts/backup_db.py
```

Архив PostgreSQL появится в `backups/`. Его нужно скопировать с хоста в
отдельное надёжное место. Код и дамп базы — разные части резервной копии.
Восстанавливать дамп следует через `pg_restore` в пустую базу при остановленных
`web` и `worker`; сначала проверить восстановление в отдельной тестовой среде.

Для продолжения разработки в новом чате приложите `soft-trainer-mlp.zip` и
попросите прочитать README, `CHANGELOG.md`, `BACKLOG.md` и `docs/VERIFICATION.md`. Для истории изменений
на своём компьютере можно выполнить `git init` и сохранять этапы коммитами;
пароли, данные и резервные копии уже исключены через `.gitignore`.
